## 0.11.0 — Google Sheets backup

The app's own storage is browser localStorage only — no cloud backup of any kind. The previous
app had a live Google Sheets sync as a real off-device backup; this restores that.

- `src/lib/googleSheetsSync.js`: loads Google Identity Services lazily (only when the user opens this feature, not on every page load), requests an OAuth access token scoped to `spreadsheets` (silent mode for auto-sync, consent-popup mode for the first connect), and `pushTransactionsToSheet()` mirrors the current transaction list into the sheet's "Transactions" tab by clearing the range and rewriting it — so edits and deletes in the app disappear from the sheet too, rather than leaving an ever-growing append log.
- `src/lib/storage.js`: `writeRaw()` now dispatches a `mf:write` window event on every write. This app has no shared reactive store (each screen reads its own local copy on mount), so this is the only way to notice "the transactions list changed" regardless of which screen — Transactions, an import, the legacy importer, Duplicates — made the change.
- `src/lib/useGoogleSheetsAutoSync.js`: listens for that event and, when sync is connected, pushes to the sheet ~5 seconds after the last change. Mounted once at the `App.jsx` shell level so it runs no matter which screen is active. A failed silent token refresh (e.g. the browser session's Google consent expired) marks sync as disconnected rather than popping up a Google sign-in window unprompted.
- **Settings → Google Sheets backup**: new section — OAuth Client ID + Sheet ID fields, Connect/Reconnect, manual Sync now, Disconnect, and a status line with the last-synced time. Needs a Google Cloud OAuth Client ID (Web application type, authorized origin `https://bsharakhoury.github.io`) set up once outside the app — this is an account-level step only the user can do, so I can't automate it.
- `src/lib/migrations.js`: bumped `SCHEMA_VERSION` to 4, added a migration seeding `settings.googleSheets = { clientId: '', sheetId: '', connected: false, lastSyncedAt: null }`.
- Verified in the browser: the Connect flow genuinely loads Google's real Identity Services library and attempts a real OAuth consent popup (blocked by the sandboxed browser's popup policy, as expected in an automated environment — the actual popup click has to happen in a real browser); the empty-fields validation message and the popup-failure error both surface cleanly with no crash. The write→event→debounced-push chain is covered by `tests/googleSheetsSync.test.js` with a mocked fetch (clear-then-write sequence, both failure paths, and the row-mapping itself).

## 0.6.0 — Phase 5: Invoices + VAT

## 0.4.0 — Phase 3: Import engine

- Parsers (each with a fixture + test under `tests/parsers/`):
  - `src/lib/parsers/mashreqSms.js` — pasted Mashreq SMS alerts. **No sample SMS text was available**, so the exact wording of each format is a documented assumption, grounded in the brief's own in-sentence date example ("on Monday, 10 August 2026, 1:26 pm") and the raw-merchant patterns recovered from the legacy backup (e.g. `"DISTROKID MUSICIAN, +14153666101 (USD 24.99)"`). Recognises `P_MASHREQ_DEBIT`, `P_NEO_VISA`, `P_ACCOUNT`, Aani debit/credit, and salary credit; strips `Available Balance …` before any amount match so it's never read as the transaction amount; supports a date-only header line whose date applies to following lines that have no in-sentence date; converts foreign-currency purchases with the Settings FX rate.
  - `src/lib/parsers/rakCsv.js` — RAK's `Account_Transactions_CSV*.csv` export, exactly per the brief's column shape (a metadata header block, then quoted/multiline description rows). `CHARGE COLLECTION … INCL VAT` and `RAKvalue Monthly Fee` → LH – Bank Fees with `inputVat = amount − amount/1.05` and `reclaimable: true`; `OUTWARD T/T … Federal tax authority` → LH – VAT; `PURCHASE TRXN.-REV` → refund even when it lands in the credit column.
  - `src/lib/parsers/rakStatement.js` — RAK statement text pasted from online banking (as opposed to the CSV upload). **No sample was available**; assumes a date/description/`AED amount DR|CR` block shape and shares its categorisation rules with `rakCsv.js`.
  - `src/lib/parsers/stripeCsv.js` — Stripe's balance-history CSV. A payout row → `transfer`; a charge/session row → Leaf & Hook – Wellness income, plus a separate LH – Bank Fees expense row for its fee.
  - `src/lib/parsers/merchants.js` — `normaliseMerchant()`; built-in `MAJID AL FUTTAIM HM` → Carrefour alias.
  - `src/lib/parsers/categorise.js` — applies a matching user `merchantRule` (string or `/regex/flags`), else a built-in merchant alias's default category (e.g. Carrefour → Food (Groceries)).
  - `src/lib/parsers/index.js` — `detect()`: picks a parser from an uploaded file's name/header shape, or from pasted-text phrasing.
  - `src/lib/csv.js` — small RFC4180-ish CSV tokenizer (quoted fields, embedded commas/newlines) shared by the CSV parsers — no new dependency.
  - `src/lib/duplicates.js` — `bankRef` first, else `date|amount|rawMerchant`, per the brief.
- `src/components/import/ImportBox.jsx` + `ImportPreview.jsx`: paste box or CSV upload → detected rows shown with per-row editable category/ledger/account, a "possible duplicate" flag (unchecked by default, still addable), a "remember this merchant" checkbox that writes a `merchantRule`, two-step confirm, then commit.
- Transactions screen: new "Import" button opens this flow; committed rows get a shared `importBatchId` and an `importBatches` record; the whole batch's Undo toast (6s) removes exactly what was added.
- Settings → new "Import batches" section lists past batches with two-step confirm + Undo-toast removal of the whole batch.
- Verified end-to-end in the browser: pasted Mashreq SMS → preview → commit (FX conversion, Carrefour alias, Aani/salary categorisation all correct) → re-pasted the same text → the repeat was flagged and unchecked while the new line was included → "remember merchant" round-tripped through `merchantRules` and into a second import's default category → uploaded a RAK CSV → correct LH – Bank Fees/VAT/refund mapping → undid the batch from Settings and watched the transaction count drop by exactly that batch's rows.

## 0.3.0 — Legacy backup importer
